EIP Priority Lists is live in the trpa-agency/tools repo at `eip/funding-priorities.html` (apps.json id `eippriorities`, EIP category, no beta flag) with a test copy at `qa/eip/funding-priorities.html` (id `eipprioritiesqa`, beta, listed on the QA pages). The two files are one code base: `IS_QA` (the path contains `/qa/`) sets `TABLE.write` false, so the test copy reads the shared table but keeps saves in localStorage and shows a "Test copy" chip and notice; the only textual difference is asset depth (`../../assets/` in qa/eip/, `../assets/` in eip/). Promote a change by copying qa/eip/ over eip/ and changing `../../assets/` to `../assets/`. History: the row-based prototype was built Oct. 30, 2026 at `qa/eip/priority-lists.html`, overwrote the earlier EIP Funding Priorities app at `qa/eip/funding-priorities.html` on Nov. 1, and moved to eip/ the same day; the prototype file was deleted, so its old links 404. The last version of the earlier app is commit 60bdc2f on mtb-edits (merge 33d5d1e on main); the maps repo copy at eip/funding-priorities.html is an older frozen copy. Work on `mtb-edits`, merge to `main`.

**Process (FY28):** Workgroup leads keep their group's list current in the tool. The deadline notice at the top of the panel says working group lists are due to the EIP Coordinating Committee by Dec. 18, 2026 (Dec. 22 until Nov. 1) and tells people to follow steps 1-5; the About info button sits in that notice's actions-end slot. The LTRA request goes to the congressional delegation March 15, 2027 (`FY.label` and `DOC.fy` carry the cycle names). ESA's Work Order 004 (due June 30, 2027) will add a Priority Lists feature to the Tracker with the same per-pick fields, so the master sheet CSV is meant to seed it.

**Model:** one row per change to one project on one working group's list; rows are only added; for each (listkey, wg, eip) the newest row wins (CreationDate, then OBJECTID); tier 0 removes a project; moving a project between lists also writes a tier 0 row for the old list. The FY27 baseline is the newest survey record per working group (older duplicates dropped, not merged; "Other" skipped); Mason decided Oct. 30, 2026 to skip last year's master sheet (the seed script's `--sheet` option stays for a later cycle). FY28 rows are the edits. The list belongs to the working group, not an email, and each row carries who and agency from the panel (name is required to save).

**Page:** Calcite 5.0 and AG Grid Community 33.3.2 only, no map, no charts, no Plotly. Panel order, from the EIP coordinator's Oct. 30 and Nov. 1 reviews: deadline notice, 1. Your name and agency, 2. Your working group (buttons with counts, plus All projects), 3. Priority list (LTRA/Other switch and two numbered steps: click a project, fill in the pop-up), 4. Add a project (search shows all active projects with their On lists), 5. Print or export (Print master sheet, Print LTRA priority list, Master sheet CSV). The table is read-only; its header count line shows the group's request total and its Priority 1 total (Nov. 3, 2026). The pop-up (`#detailCard`) has Save and Cancel plus info buttons for Priority and Note; under Request, the Tracker LTRA request is a button that fills the field and the unfunded need is plain text (same date, from the EIP coordinator), and the subtitle line still shows both numbers. Print master sheet is landscape, one section per group with totals, columns Priority, Project, Implementer, EIP #, request, Criteria, Note (no Changed column since Oct. 30). The CSV follows the master sheet layout with Changed by, Changed on, and Tracker stage, and no Tracker LTRA request (same review). Print LTRA priority list drafts the public FY2027 document layout (`DOC` constant: summary box lines and program sections map to working groups; Recreation rolls into the SWQIC line; unnamed groups get an "Other working groups" section), every text block `contenteditable`, amounts from the LTRA lists. `CRITERIA` holds the 10 LTRA criteria from the Oct. 2026 review (Measurable progress, Threshold contribution, Multiple benefits, Non-federal leverage, Stakeholder support, Federal nexus, Agency capacity, Federal funding history, NHPA compliance, ESA compliance). `WG_SHORT` is the roster: TFFT, Water Infrastructure, SWQIC, TWIG, AIS, LCT, Recreation, Accountability, Other.

**Hosted table:** created and seeded by `scripts/eip_priority_lists_table.py --create --seed` (arcgispro-py3, `GIS("pro")`; service `EIP_Priority_Lists`, table `picks`; fields fy, listkey, wg, eip, project, tier, request, criteria, note, who, agency, source, editor tracking; capabilities Create,Query; shared with everyone; `--dry-run` reported 77 picks across 7 groups). Mason had Claude run it on Nov. 1, 2026: item 5f2e41e79e6848518aa2851980cdc6ad, table `https://services5.arcgis.com/fXXSUzHD5JjcOt1v/arcgis/rest/services/EIP_Priority_Lists/FeatureServer/0`, 77 FY27 rows, anonymous query and add verified (a test add was deleted as owner). `TABLE.url` is set, so test mode is off. While `TABLE.url` is empty the page runs in survey mode: baseline parsed from the survey view client-side, edits in localStorage `eipPriorityLists.edits.v1`, name and agency in `eipPriorityLists.who`. Rows cannot be removed by the app (Create only); wrong rows are deleted as the owner in ArcGIS Online or with the arcgis API. A new cycle needs the FY constants changed and a way to seed the next baseline from the table rather than the survey; the script does not do that yet.

**Survey123 plumbing (baseline source):** Form `06f26df8a2ab4ddab59c4f82ee06d8e5` ("EIP Funding Priorities picks", TRPA ArcGIS Online, owner mbindl, public, multiple submissions). The source layer is `survey123_06f26df8a2ab4ddab59c4f82ee06d8e5` on services5.arcgis.com/fXXSUzHD5JjcOt1v (item 0a58e883e3d0405aa9827815f58b677a). The tool reads a public view that omits email, `EIP_Funding_Priorities_picks_public_view/FeatureServer/0` (item 606033db94774658a6677d907b0c7548), filtered to `SURVEY.round` FY28. The submission layer `survey123_..._form/FeatureServer/0` is Create only with ownership access control, so Survey123's edit or resubmit cannot save and anonymous users cannot update; the new app never writes to it.

Published field names are frozen: reviewer_name, reviewer_email, agency, reviewer_key_filled_in_by_the_t, funding_round_filled_in_by_the, your_ranked_picks_project_numbe, notes, scenario_url. On Oct. 7, 2026 picks_text and notes_text (50,000 characters) were added to the parent layer with EIP/scripts/update_priorities_survey_fields.py, because ArcGIS Online cannot lengthen a text field (updateDefinition reports success and keeps 4,000) and views cannot take new columns. Read the long fields first.

**Survey record format:** the picks field holds a header line "Working group: <name>", then one line per pick: "LTRA P1 $500,000 01.02.01.0005 Project name" (list, tier, optional request, EIP number, name). Notes are "number: Criteria addressed: a, b. free text" lines. Both the page's `surveyBaseline()` and the script's `survey_baseline()` parse this; the older "1. id name" and "id:rank" lines (ranks 1-3, 4-6, 7+ map to tiers 1, 2, 3) only mattered to the earlier app.

**Earlier app (Oct. 7 to Oct. 30, 2026, commit 60bdc2f):** reviewers drafted picks in the browser and posted one record per send with applyEdits; reviewers were deduped by reviewer_key (FNV-1a of the lowercased email, newest per key within the round), so Replace meant a newer record under the same email and "Edit Previous LTRA Priority Picks" merged the earlier record into the draft. It had an ArcGIS map, Plotly charts, a focus area filter, Borda voting (off since Oct. 19 behind `FEATURES.voting`), an Exclude what-if button (removed Oct. 28), and a staff review pass (Oct. 22 to 29) that made the table read-only with a docked pop-up, a Group picks column filter, a check-mark Done button, and a much simpler panel. It was replaced because resending whole lists confused everyone and a lead on another computer could drop the group's earlier list.

**Why:** The LTRA process ranks by Priority 1, 2, or 3 with a dollar request per project, grouped by working group. The "LTRA request > 0" Tracker rule matched only 33 of 65 active projects on the FY27 list, so list membership is a working group choice and Tracker LTRA data is only a hint. Every EIP project has a focus area; the 38 Unassigned projects in the snapshot are non-EIP Tracker entries, which the tool never shows. The permission classifier blocks Claude from changing sharing on ArcGIS Online items, so Mason does those clicks.

**How to apply:** Project data comes from [[eip-data-snapshot]]; site context is in [[trpa-tools-site]]. Keep `SURVEY.round` FY28 for the baseline read even after the table exists; the survey is history, not an input, once `TABLE.url` is set and the FY27 rows are seeded.
