# Forms

How the BMP program's forms are built and published, and why the old ones broke. Started Oct. 21, 2026.

## The rule

Fillable PDFs that must work in a browser are **AcroForms** made with Acrobat or generated by code. **LiveCycle Designer (XFA) forms do not open in Chrome, Edge, Firefox, or Safari**; they show a "Please wait..." page and only work in Adobe Reader. Adobe discontinued LiveCycle, the person who built TRPA's XFA forms has left, and nothing new should be built that way.

Submissions with attachments (photos, invoices, logs) are **web forms, not PDFs**. Microsoft Forms cannot accept file uploads from anyone outside the TRPA tenant, so property owners and contractors could not attach anything. Survey123 (public form, attachments, APN, results in the TRPA GIS next to the BMP Database) is the fit; Accela Citizen Access already handles Small BMP Retrofit Plans.

## Generated PDFs

`scripts/build_forms.py` draws each form with reportlab and adds the fields as standard AcroForm widgets, so the file opens and fills in every browser and prints cleanly. The layout and field names are in the script; change them there and rerun:

    "C:\Program Files\ArcGIS\Pro\bin\Python\envs\arcgispro-py3\python.exe" scripts/build_forms.py

Outputs land in `forms/`. The site links them directly (`forms/bmp-maintenance-log.pdf`), so a rebuild is a commit, not an upload to another server.

Field names in the maintenance log follow `section_row_column` (for example `infiltration_trench_ok`), which keeps exports from Acrobat readable if staff ever collect filled copies.

## Survey123 forms

`scripts/build_survey123_forms.py` writes the two XLSForm workbooks. Each has the three standard sheets (`survey`, `choices`, `settings`). Publishing follows the order in "Integration with the BMP Database", Step 3: for testing first, shared with the program group, and with Everyone only when the sync job runs. The steps:

1. Open Survey123 Connect (desktop), sign in to the TRPA ArcGIS Online organization, choose New survey, then File, and pick the `.xlsx`.
2. Check the preview on the right. Groups appear as pages; the APN question validates the four county formats; photo repeats allow up to 10 (maintenance) or 6 (evaluation).
3. Publish. Survey123 creates a hosted feature layer with one row per submission and the photos and files as attachments.
4. In the Survey123 website, under Collaborate, share the survey with Everyone (public) and copy the survey link. Sharing the results stays with the program group.
5. Put the link in `assets/site.js` (`BMP.config.maintenanceForm` and `BMP.config.evaluationForm`); the Maintenance page and the search's "Request an evaluation" button switch from the email path to the form when those values are set.

Edit the questions in the script, not in Connect, so the design stays in the repo; republishing from a changed XLSForm keeps the same survey and feature layer as long as the field names do not change (adding questions is fine; renaming is a schema change).

Two things Connect does that matter when the script changes:

- Connect copies the workbook into `%USERPROFILE%\ArcGIS\My Survey Designs\<title>\<title>.xlsx` and opens that copy in Excel, which locks it. To load a regenerated workbook: close the copy in Excel, copy the new file over it, open the survey, and click Update. Connect does not read the repo file again on its own.
- Survey123 has no `acknowledge` question type; Connect renders one as an unsupported "trigger" with no label. The certification at the end of the maintenance form is a required `select_multiple` with a single choice instead.

Later: the hosted feature layer can be joined to the BMP Database by APN, and a Survey123 webhook or a scheduled script can email the program when a submission arrives.

## Integration with the BMP Database

Decided Oct. 21, 2026, closing the prototype phase: the BMP Database on the agency SQL Server stays the system of record, and the next phase integrates the site with it instead of standing up a parallel store. The GIS Manager, who built and maintains the database and the BMP Toolkit, does this phase with Claude. The collection-geodatabase plan and the hosted-layer-plus-sync idea from the prototype are kept at the end of this section as fallbacks. Nothing has been created in any geodatabase.

Tech, none of it new to the agency: T-SQL views in the BMP Database, ArcGIS Pro publishing to the federated server on maps.trpa.org, Survey123 Connect with hosted layers in the portal, Python in arcgispro-py3 with the ArcGIS API for Python and pyodbc, Windows Task Scheduler on the GIS server for the job, and the agency SMTP for notifications (a Survey123 webhook into Power Automate is the no-code option for the email alone).

Two constraints shape the design. Survey123 writes only to an ArcGIS feature service, and photo attachments need a geodatabase behind that service, so the web forms cannot write straight into the BMP Database; something has to carry submissions across. And the static site has no server of its own, so everything it reads comes through services on maps.trpa.org.

### What the toolkit does today

The old site's BMP Toolkit (tahoebmp.org/bmptoolkit, observed Oct. 21, 2026) is the "BMP Evaluation and Tracking Tool" on top of the BMP Database:

- The public search (`SearchBMP.asp`) reads the database by APN, address, owner, or certificate number and shows status, certificate date, county, permeability (KSAT at 12 inches), fire district, area-wide name and treatment, and disclosure date.
- The property summary (`quickReport.asp?ParcelID=`) shows property, site (soil type, KSAT, soil constraint, slope, land capability, SEZ or shorezone, priority watershed), compliance (implementation required by, certificate issued and updated dates, source control certificate, retrofit only, disclosure received and date, enforcement action, maintenance requested), evaluation (agency, requested and evaluation dates, evaluator), and the maintenance documents on file for the parcel. Owner name shows only after login.
- `printCertificate.asp`, `printSourceCertificate.asp`, and `printEvaluation.asp` render certificates and evaluations from the database.
- `RequestEvaluation.asp` no longer has a form; it says no evaluation is on file and points to the hotline (free evaluations ended in 2015). `SupportRequest.asp` is a four-field help request form.
- The agent login (`login.asp`) is where staff and Conservation District agents enter evaluations, certificates, flags, and maintenance documents.
- The map service `BMP_Status/MapServer/5` is a view that joins the SDE parcels feature class to the BMP Database by APN: its BMP columns carry doubled SQL Server nvarchar lengths, 'True' and 'False' text, and dates as text. So the database is already reachable from the SDE's SQL Server, which is the hook for everything below.

The new site keeps the public half of that (search, summary, certificates by way of the Parcel Tracker, documents, forms) and leaves the staff half (the agent login and tracking tool) where it is.

### Step 1: discovery, read-only

The GIS Manager runs `scripts/dump_bmp_schema.py` against the BMP Database with a read-only login. It reads `INFORMATION_SCHEMA` and the catalog views and writes `docs/bmp-database/schema.md`, `schema.json`, and `modules.sql` (view, procedure, and function definitions). It never records the server name or credentials, and it writes nothing to the database; review the output before committing it, since the repo is public. Connection settings go in `scripts/.env` (gitignored; `scripts/.env.example` lists the keys). From that output, Claude drafts the data dictionary and the two of them settle:

- Which tables hold parcel status, certificates (including source control), evaluations, disclosures, enforcement and maintenance flags, and maintenance documents, and how APNs are stored (format, dashes, county prefixes).
- Where the maintenance document files live (table, file share, naming) and how `quickReport.asp` lists them.
- How the `BMP_Status` view is defined, who else reads the database (LT Info Parcel Tracker, the certificate prints, Accela), and which stored procedures the ASP pages call.
- The rules behind the status symbols: what sets and clears Maintenance Requested, Certificate Updated, Disclosure Received, Enforcement, and Revoked.
- Which fields are public. The toolkit hides owner names from anonymous users; the current public service exposes them.

### Step 2: reads, the site gets its data from the BMP Database

- A public-safe SQL view (no owner names or mailing addresses unless the program decides otherwise) joined to parcels by APN, published on maps.trpa.org as a map or feature service that replaces or extends `BMP_Status/MapServer/5`. It carries what the property summary shows today: site data, compliance fields and dates, evaluation agency and date, and the maintenance documents on file (name, date, link).
- `search.html` and `map.html` switch to that service and the search's detail panel grows to the summary fields. Code change, Claude.
- Certificates: the Parcel Tracker print stays the path for now. If the program wants printing on the site, the certificate can be rendered in the browser from the service fields (jsPDF is already in the stack); the evaluation print is the same pattern.
- Documents on file: if the files are on a share the web cannot reach, the view carries names and dates only, and the download stays a staff request until hosting is decided.

### Step 3: writes, submissions land in the BMP Database

- Intake stays Survey123: the two forms in `forms/survey123/` are published as hosted feature layers in the portal (the default publish, no geodatabase work). The field names in the XLSForms are the mapping keys, so they do not change.
- A scheduled job, `scripts/sync_submissions.py` (to be written in this step, arcgispro-py3, run from Task Scheduler on the GIS server), reads new submissions by GlobalID and edit date, inserts rows into the tables the toolkit uses for maintenance documents and requests, copies the photos and files into the document store with the toolkit's naming, sets the flags per the Step 1 rules, and emails the program. The field-to-column mapping lives in `scripts/config.yaml`, not in code, so the GIS Manager can change it.
- Alternative if the program would rather not have an ArcGIS layer in the loop: a small API on an agency server that receives the form POST and writes to the database directly, which is how the toolkit's own pages work. It costs custom code, hosting, spam protection, and file storage; decide at the end of Step 1.
- Go-live order: publish the surveys for testing shared with the program group, run the job against test submissions, then share the surveys with Everyone and put the links in `assets/site.js` (`BMP.config.maintenanceForm`, `evaluationForm`).

### Step 4: staff workflow stays in the tracking tool

Staff keep reviewing and entering certificates, evaluations, and flags in the tracking tool, which keeps running on its server after the public pages retire. Submissions arrive in its tables from Step 3 with an email notification. The decision about the tracking tool's long-term home (keep it, move data entry into Pro, or a staff Survey123 form) is separate and does not block the site.

### Step 5: cutover

Redirects from tahoebmp.org per `DEPLOY.md`, the document files (488 MB) either moved into the repo or left on the old server, DNS for bmp.trpa.gov with DTS, then the public pages retire while the toolkit's staff pages stay reachable.

### Fallbacks considered

- **Hosted layer plus a sync into the SDE.** Publish from Connect as is; a scheduled script mirrors rows and attachments into an SDE feature class. It is Step 3 without the BMP Database on the far end, which is why it stayed a fallback.
- **Feature services published from the collection geodatabase.** The prototype's working plan: one point feature class per form plus a related table per repeat (GlobalIDs, attachments, editor tracking, relationship class on `parentglobalid`), published Create-only on the federated server, with `submission_url` set in the XLSForms and `form_id` equal to the layer name. It gives staff a feature class in the transaction geodatabase but leaves the BMP Database out of the loop, so a second copy of every submission would exist. Dropped Oct. 21, 2026.

## Retiring the old files

When the Survey123 forms are live and the AcroForm log is linked, the legacy `Maintenance_Log_interactive_form.pdf` and `Maintenance_Log_static_form.pdf` can be removed from the old server, and the maintenance page's note about Adobe Reader goes away. The disclosure form stays as the static PDF until the program decides whether to rebuild it as an AcroForm (same script, one more spec) or move it into a web form.
